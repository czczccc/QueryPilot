## 1. 产品概述

QueryPilot 将用户的自然语言需求转换成结构化搜索计划，通过多个公开搜索提供方召回候选结果，再对每条结果做**严格的有效性验证**（不是只查 HTTP 状态码），最终输出带置信度、已验证可用的链接清单。作为 AI/FDE 岗位作品展示端到端交付能力。

### 1.1 问题陈述

传统搜索返回大量"看起来存在"的结果，但其中很多链接实际已失效（删除、过期、被举报），用户需要逐个点击验证。QueryPilot 解决的问题：**在展示结果之前，系统自己先完成有效性验证**，把「有效 / 已失效 / 待确认」客观区分出来。

### 1.2 产品目标

- 用一句自然语言获得**已验证可用**的资源链接清单，而不是一堆需要手动点击确认的网页结果；
- 展示查询理解、多源聚合、失败降级、严格验证和可观测性；
- 形成一个可在线访问、可复现部署、适合面试演示的完整项目；
- 从早期的个人桌面原型升级为架构清晰、可测试、合规声明的 Web 产品。

### 1.3 非目标

- 不托管文件，不提供破解、绕过付费墙或侵权下载能力；
- 不做用户账户、收藏、搜索历史或团队协作；
- 不承诺搜索结果绝对正确、实时或完整；
- 不在 MVP 中引入数据库、向量数据库或多 Agent 框架；
- 不为每个垂直领域接入专属商业 API。

## 2. 用户与场景

### 2.1 目标用户

首要用户是需要快速获得"真实可用资源链接"的普通互联网用户。次要用户是查看项目的招聘者和工程师，他们需要快速理解系统的产品价值、架构取舍和工程质量。

### 2.2 核心使用场景

1. 影视/剧集：输入作品名（可带清晰度、别名、英文名），获取各渠道的可用分享链接；
2. 资源核验：对已有链接清单做批量有效性检查，区分有效与失效；
3. 通用调研：围绕一个自然语言问题收集可追溯的来源并验证可达性。

### 2.3 核心用户故事

- 作为用户，我希望输入"漫长的季节 4K"就能拿到**点开确实有效**的链接，而不是挨个试错；
- 作为用户，我希望系统显示每条链接的验证状态（有效/已失效/待确认）和提取码，便于直接使用；
- 作为用户，即使某个 AI 或搜索服务失败，我也希望得到可理解的降级结果；
- 作为面试官，我希望在几分钟内看出候选人如何处理外部 API、错误、测试、并发和部署。

## 3. 产品范围与优先级

### 3.1 P0：MVP 已完成

#### FR-01 搜索输入

- 首页提供自然语言输入框和搜索按钮；
- 输入去除首尾空白后长度必须为 2–200 个字符；
- 空输入、超长输入给出明确提示；
- 提供 3 个可点击示例。

#### FR-02 意图解析与查询改写

- DeepSeek 将输入解析为 `resource`、`quality`、`aliases`、`english_name` 和 5~6 个 `search_suggestions`；
- 模型输出必须经过归一化 + Pydantic 校验，不可信 JSON 不得直接进入搜索层；
- DeepSeek 超时、限流或输出无效时，系统使用规则降级（关键词清洗 + 默认查询词）并标记降级模式；
- 输入为豆瓣链接（`movie.douban.com/subject/<id>`）时，先抓取移动版页面识别片名/年份/类型，再进入解析；响应携带 `douban` 元信息。

#### FR-03 多源检索

- 接入 Tavily（API）与 Bing 中文（HTML 解析）与垂直搜索站三路引擎；
- 查询按受控并发执行（Semaphore 限流），每个调用设置超时；
- 单个引擎失败不影响其他引擎结果（部分成功）；
- 返回每个提供方的成功状态、结果数量、错误类型和耗时，不向前端暴露密钥或内部堆栈。

#### FR-04 结果提取与去重

- 从搜索结果的 URL、摘要和资源页正文中提取目标平台分享链接（正则 + 深度抓取）；
- 自动识别提取码（4 位）；
- 按唯一分享标识去重，相同标识只保留一条；
- 深度抓取页面数量受控（上限 10 页），跳过高风险反爬域名。

#### FR-05 严格有效性验证

- 逆向目标平台分享页前端（share.js），两步 API 验证：先取 stoken（分享不存在/已失效返回 404），再查文件列表（无文件视为已失效）；
- 每条链接标记 `valid` / `invalid` / `unknown`，而不是只看 HTTP 200 壳页假象；
- 验证并发执行（8 路限流）并设置超时，不影响整体响应。

#### FR-06 结果展示

- 页面展示资源识别结果（资源名/清晰度/别名/英文名）、查询变体、流水线指标；
- 链接清单展示：分享链接、提取码、置信度、验证状态徽章（有效/已失效/待确认）、来源；
- 「只看有效链接」开关默认开启，失效链接置灰置底；
- 支持单条复制与复制全部（仅可见项）；
- 外部链接新标签页打开并使用安全 `rel` 属性；
- 支持无结果、部分成功、完全失败三种状态；
- 页面在 375px 和桌面宽度下均可正常使用。

#### FR-07 API 与健康检查

- `POST /api/search` 接收查询并返回完整搜索响应；
- `GET /health` 返回应用状态，不检查或泄露密钥值；
- FastAPI 自动生成的 `/docs` 能展示请求和响应模型；
- API 对客户端错误返回稳定的 4xx，对外部依赖错误采用部分成功响应或受控 503。

#### FR-08 安全配置

- 所有密钥只从环境变量读取；
- `.env`、`config.json`、缓存和 Python 编译产物必须被 Git 忽略；
- 仓库提供不含真实值的 `.env.example`；
- Git 历史零密钥（已审计），提交 GitHub 前必须秘密扫描。

### 3.2 P1：候选

- 进程内速率限制与请求 ID 展示；
- 导出 TXT 链接清单；
- 通过 Server-Sent Events 实时展示阶段进度；
- 保存演示截图和 60 秒演示视频。

### 3.3 P2：后续路线

- 更多垂直搜索站接入（统一 `SearchProvider` 接口）；
- 用户反馈驱动的排序评估集；
- 缓存、配额管理和后台任务；
- 支持自定义搜索提供方插件。

## 4. 用户流程

```mermaid
flowchart LR
    A["输入自然语言（资源名/清晰度）"] --> B["校验输入"]
    B --> C["DeepSeek 解析意图与生成查询变体"]
    C --> D["多引擎受控并发检索"]
    D --> E["提取候选分享链接 + 提取码"]
    E --> F["按唯一标识去重"]
    F --> G["并发严格验证（token+detail）"]
    G --> H["置信度排序 + 验证状态展示"]
    C -. "失败" .-> R["规则降级"]
    R --> D
    D -. "单引擎失败" .-> E
```

## 5. 交互与页面状态

### 5.1 首页

- 产品名称、单句价值主张；
- 主搜索框、提交按钮和示例查询；
- 简短说明结果来自公开搜索源并经有效性验证。

### 5.2 搜索中

- 禁止重复提交同一个请求；
- 展示"解析资源、搜索、验证可达性"的加载提示，说明通常需要 20~60 秒；
- 前端 120 秒超时保护（AbortController），超时给出明确错误文案。

### 5.3 搜索完成

- 顶部显示资源识别结果和查询变体；
- 指标区显示总耗时、原始/去重数量、各引擎状态、是否降级；
- 链接按验证状态排序：有效 → 待确认 → 已失效；
- 「只看有效链接」开关默认开启。

### 5.4 错误与降级

| 场景 | 用户反馈 | 系统行为 |
| --- | --- | --- |
| 输入不合法 | 就地显示校验错误 | 不调用外部服务 |
| DeepSeek 失败 | 显示"已使用基础查询" | 规则生成查询 |
| 单个引擎失败 | 引擎状态显示 error | 返回其他引擎结果 |
| 全部引擎失败 | 显示重试建议 | 受控 503，不显示堆栈 |
| 无有效结果 | 建议换别名/英文名/加清晰度重试 | 返回清单与验证状态 |

## 7. 非功能需求

### 7.1 性能与可靠性

- 单次搜索目标 P95 小于 30 秒（实测 15~27 秒，含多引擎并发与验证）；
- 单个外部调用超时不超过 8 秒（验证步骤 8 秒），深度抓取 10 秒；
- 一个引擎失败时仍能返回其他引擎结果；
- 不因模型返回异常 JSON 或单引擎崩溃导致未处理的 500 错误。

### 7.2 安全

- API Key 不进入 HTML、日志、API 响应和 Git 历史；
- 所有用户可见文本使用 `textContent` 渲染（防 XSS），页面不渲染未转义的第三方 HTML；
- 只允许 `http` 和 `https` 结果链接；
- 日志只记录请求 ID、阶段、耗时和错误类别，不记录密钥。

### 7.3 可维护性

- AI 客户端、搜索提供方、验证层、编排服务和 Web 层分离；
- 第三方响应在适配器边界转换，不向核心领域泄漏供应商字段；
- 链接提取、验证、置信度计算为纯函数并具备单元测试；
- README 中的启动命令必须可复制执行。

### 7.4 可访问性

- 搜索输入具有关联标签；
- 键盘可以完成搜索和访问结果；
- 焦点状态可见，文本颜色满足基本对比度；
- 加载和错误状态使用可被辅助技术识别的状态区域（aria-live）。

## 8. 成功指标与验收标准

MVP 完成必须同时满足：

- 3 个示例查询均能完成端到端搜索并展示**已验证**链接清单；
- 人为让 DeepSeek 或一个引擎失败时，页面能正确降级；
- 同一分享链接不会重复出现（按唯一标识去重）；
- 失效链接能被严格验证层识别（`invalid`），而不是被当作"可达"；
- `python -m pytest -q`（48 项）和 `python -m ruff check .` 通过；
- Docker 镜像可以构建并通过 `/health` 检查；
- GitHub 中不存在真实密钥，秘密扫描无告警；
- 在线 Demo 可从 README 访问：http://124.223.112.9:8000。

## 9. 风险与约束

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Bing HTML 结构变化 | 该引擎召回下降 | 解析逻辑集中在 quark.py，结构变化时快速修复；正则已适配新版（链接内嵌标题） |
| 分享链接时效性强 | 有效结果少 | 多引擎扩大召回面 + 严格验证只展示真实可用的 |
| 目标平台 API 变动 | 验证失效 | 验证逻辑集中在 verify_quark，重新逆向 share.js 即可修复 |
| 第三方内容存在版权或错误 | 展示风险 | 只链接公开来源，提供免责声明，仅供合规用途 |
| 外部 API 配额或超时 | Demo 不稳定 | 超时、部分成功、规则降级 |
