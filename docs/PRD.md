## 1. 产品概述

QueryPilot 将用户的自然语言需求转换成结构化搜索计划，通过多个公开搜索提供方召回结果，再进行标准化、去重、排序和解释。首版面向需要快速探索游戏、影视、音乐、软件或一般主题的用户，同时作为 AI/FDE 岗位作品展示端到端交付能力。

### 1.1 问题陈述

当用户只有模糊目标而没有准确关键词时，传统搜索要求用户反复改写查询、打开多个网站并手动判断结果质量。用户缺少一个能解释“系统理解了什么、搜索了什么、为什么返回这些结果”的轻量工具。

### 1.2 产品目标

- 让用户用一句自然语言在 15 秒内获得结构清晰、来源明确的搜索结果；
- 展示查询理解、查询扩展、搜索聚合、失败降级和可观测性；
- 形成一个可在线访问、可复现部署、适合面试演示的完整项目；
- 将原有垂直网盘搜索原型升级为合规的通用公开信息搜索产品。

### 1.3 非目标

- 不托管文件，不提供破解、绕过付费墙或侵权下载能力；
- 不做用户账户、收藏、搜索历史或团队协作；
- 不承诺搜索结果绝对正确、实时或完整；
- 不在 MVP 中引入数据库、向量数据库或多 Agent 框架；
- 不为每个垂直领域接入专属商业 API。

## 2. 用户与场景

### 2.1 目标用户

首要用户是希望用自然语言快速探索公开信息的普通互联网用户。次要用户是查看项目的招聘者和工程师，他们需要快速理解系统的产品价值、架构取舍和工程质量。

### 2.2 核心使用场景

1. 游戏：寻找满足人数、语言、平台或玩法约束的游戏资料；
2. 影视：查找作品介绍、演职员信息、评论或正版观看渠道；
3. 音乐：查找歌曲、艺人、专辑资料和正版平台页面；
4. 软件：查找产品官网、文档、教程和替代方案；
5. 通用调研：围绕一个自然语言问题收集可追溯的网页来源。

### 2.3 核心用户故事

- 作为用户，我希望直接描述目标和限制条件，而不是先学习搜索语法；
- 作为用户，我希望看到系统提取出的意图，发现理解错误时能调整输入；
- 作为用户，我希望结果带有原始来源和匹配理由，以便自主判断；
- 作为用户，即使某个 AI 或搜索服务失败，我也希望得到可理解的降级结果；
- 作为面试官，我希望在几分钟内看出候选人如何处理外部 API、错误、测试和部署。

## 3. 产品范围与优先级

### 3.1 P0：MVP 必须完成

#### FR-01 搜索输入

- 首页提供一个自然语言输入框和搜索按钮；
- 输入去除首尾空白后长度必须为 2–200 个字符；
- 空输入、超长输入和重复提交需要给出明确提示；
- 提供 3 个可点击示例，覆盖游戏、影视和软件场景。

#### FR-02 意图解析与查询改写

- DeepSeek 将输入解析为 `resource_type`、`keywords`、`constraints` 和 3 个 `query_variants`；
- `resource_type` 允许 `game`、`movie`、`music`、`software`、`other`；
- 模型输出必须经过 Pydantic 校验，不可信 JSON 不得直接进入搜索层；
- DeepSeek 超时、限流或输出无效时，系统使用规则生成查询并标记为降级模式。

#### FR-03 搜索源检索

- MVP 接入 Tavily 搜索源，适配器保留统一接口便于后续扩展；
- 搜索提供方实现统一接口，单个提供方失败不影响其他提供方结果；
- 查询按受控并发执行，每个调用设置超时；
- 返回每个提供方的成功状态、结果数量、错误类型和耗时，不向前端暴露密钥或内部堆栈。

#### FR-04 标准化、去重与排序

- 所有提供方结果转换为统一 `SearchResult` 模型；
- URL 移除常见追踪参数、统一主机名大小写和末尾斜杠后进行去重；
- 相同规范 URL 只保留综合质量更高的条目，并合并来源信息；
- 排序使用可复现的确定性规则，结合关键词覆盖率、提供方相关性和内容完整度；
- 每条结果展示 0–100 的相关性分数和简短匹配理由。

#### FR-05 结果展示

- 页面展示结构化意图、查询变体、结果卡片和流水线指标；
- 结果卡片至少包含标题、摘要、URL、来源、相关性和匹配理由；
- 外部链接在新标签页打开，并使用安全的 `rel` 属性；
- 支持无结果、部分成功、完全失败三种状态；
- 页面在 375px 和桌面宽度下均可正常使用。

#### FR-06 API 与健康检查

- `POST /api/search` 接收查询并返回完整搜索响应；
- `GET /health` 返回应用状态，不检查或泄露密钥值；
- FastAPI 自动生成的 `/docs` 能展示请求和响应模型；
- API 对客户端错误返回稳定的 4xx，对外部依赖错误采用部分成功响应或受控 5xx。

#### FR-07 安全配置

- 所有密钥只从环境变量读取；
- `.env`、`config.json`、缓存和 Python 编译产物必须被 Git 忽略；
- 仓库提供不含真实值的 `.env.example`；
- 提交 GitHub 前必须轮换当前本地 `config.json` 中出现过的密钥，并进行秘密扫描。

### 3.2 P1：有剩余时间再做

- 搜索结果按资源类型或来源筛选；
- 通过 Server-Sent Events 实时展示阶段进度；
- 结果卡片支持复制链接；
- 添加简单的进程内速率限制与请求 ID；
- 保存一张演示截图和一段不超过 60 秒的演示视频。

### 3.3 P2：后续路线

- 接入 Steam、TMDB、MusicBrainz 等合规垂直数据源；
- 用户反馈驱动的排序评估集；
- 搜索历史、收藏和分享；
- 缓存、配额管理和后台任务；
- 支持自定义搜索提供方插件。

## 5. 交互与页面状态

### 5.1 首页

- 产品名称、单句价值主张；
- 主搜索框、提交按钮和示例查询；
- 简短说明数据来自公开搜索源。

### 5.2 搜索中

- 禁止重复提交同一个请求；
- 展示“理解需求、生成查询、检索、整理结果”的阶段反馈；
- 同一次请求最长等待 20 秒，超时后展示已获得的部分结果或错误说明。

### 5.3 搜索完成

- 顶部显示意图和查询变体；
- 指标区显示总耗时、原始结果数、去重后结果数和提供方状态；
- 结果按分数降序排列；
- 明确说明分数是启发式相关性，不代表真实性或质量保证。

### 5.4 错误与降级

| 场景 | 用户反馈 | 系统行为 |
| --- | --- | --- |
| 输入不合法 | 就地显示校验错误 | 不调用外部服务 |
| DeepSeek 失败 | 显示“已使用基础查询” | 规则生成查询 |
| 单个搜索源失败 | 显示该来源暂不可用 | 返回其他来源结果 |
| 全部搜索源失败 | 显示重试建议 | 返回受控错误，不显示堆栈 |
| 无结果 | 建议简化约束或更换关键词 | 返回空数组和完整指标 |

## 7. 非功能需求

### 7.1 性能与可靠性

- 在外部依赖正常时，单次搜索目标 P95 小于 12 秒；
- 单个外部调用超时不超过 8 秒，整条请求不超过 20 秒；
- 一个搜索源失败时仍能返回其他来源结果；
- 不因模型返回异常 JSON 导致未处理的 500 错误。

### 7.2 安全

- API Key 不进入 HTML、日志、API 响应和 Git 历史；
- 所有用户可见文本必须转义；
- 只允许 `http` 和 `https` 结果链接；
- 日志只记录请求 ID、阶段、耗时和错误类别，不记录密钥；
- 公开部署应设置实例级请求限制或配额保护。

### 7.3 可维护性

- AI 客户端、搜索提供方、聚合服务和 Web 层分离；
- 核心排序与去重逻辑为纯函数并具备单元测试；
- 第三方响应在适配器边界转换，不向核心领域泄漏供应商字段；
- README 中的启动命令必须可复制执行。

### 7.4 可访问性

- 搜索输入具有关联标签；
- 键盘可以完成搜索和访问结果；
- 焦点状态可见，文本颜色满足基本对比度；
- 加载和错误状态使用可被辅助技术识别的状态区域。

## 8. 成功指标与验收标准

MVP 完成必须同时满足：

- 3 个示例查询均能完成端到端搜索并展示结构化结果；
- 人为让 DeepSeek 或一个搜索提供方失败时，页面能正确降级；
- 同一 URL 的追踪参数变体不会重复出现；
- `python -m pytest -q` 和 `python -m ruff check .` 通过；
- Docker 镜像可以构建并通过 `/health` 检查；
- GitHub 中不存在真实密钥，秘密扫描无告警；
- 在线 Demo 可从 README 一键访问，冷启动限制如实说明；
- README、PRD、开发文档和任务计划与实际实现一致。

## 9. 风险与约束

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 2–3 小时范围过大 | 无法部署或测试不足 | 严守 P0，先单体和服务端渲染 |
| 外部 API 配额或超时 | Demo 不稳定 | 超时、部分成功、规则降级和示例测试桩 |
| 搜索质量主观 | 难以证明改进 | 展示查询变体、确定性评分和简单固定用例 |
| 第三方内容存在版权或错误 | 展示风险 | 只链接公开来源，提供免责声明和数据源审查 |
| 旧密钥已暴露 | 产生费用或安全事件 | 上线前轮换、移出仓库并扫描历史 |

## 10. 已确认决策（2026-08）

- 项目名称：`QueryPilot`（确认保留）；
- 部署平台：国内轻量服务器（阿里云/腾讯云，Docker + Nginx），不使用 Render；
- 首版搜索源：只接 Tavily，保留 `SearchProvider` 统一接口便于后续扩展；
- README：仅中文。
